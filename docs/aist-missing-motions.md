# AIST++: какие данные есть и как получить недостающие движения

Дата проверки: 2026-11-09. Данные лежат в `data/aist/` (вне git).

## Что есть

Архив движений `motions.zip` из релиза v1.0 официальный (контрольная сумма совпала с указанной на странице релиза), но содержит 411 последовательностей из 1408. Ключевые точки `keypoints3d.zip` полные: 1408 последовательностей, контрольная сумма совпала.

Все 30 танцоров и все 60 музыкальных пьес представлены в 411 имеющихся последовательностях. Пропали последовательности внутри каждого жанра, целых жанров среди них нет.

## План получения недостающих движений

Шаг 0. Выяснить, нет ли готового. Бесплатно и быстро.
- Просмотреть issues в репозиториях aistplusplus_dataset и aistplusplus_api: известна ли проблема, есть ли другая ссылка.
- Проверить зеркала (Hugging Face и другие) на полный `motions` и сверить с имеющимися 411 по содержимому.
- Если ничего нет, написать авторам.

Шаг 1. Разобрать, что лежит в `keypoints3d`. Первая задача для импортёра: формат файлов, число точек, частота, наличие сглаженного варианта, уверенность. Читается только Python, поэтому входит в `tools/aist_import/`.

Шаг 2. Получить каноническую позу напрямую из ключевых точек, без SMPL. Для 16 суставов канона нужны только позиции:
- есть в COCO-точках: плечи, локти, запястья, бёдра, колени, лодыжки, голова (по носу и ушам);
- вычисляются: root как середина бёдер, neck как середина плеч, chest как точка между ними.

Так канонические позы для всех 1408 последовательностей получаются без подгонки модели тела. Теряются только скрутка конечностей и детали позвоночника, а они и так не входят в измеряемое (см. `specs/core/canonical-pose.md`).

Шаг 3. Проверить шаг 2 на 411 последовательностях, где есть и ключевые точки, и официальные движения. Считаем канон двумя способами и сравниваем:
- из `motions` (вращения SMPL);
- из `keypoints3d`.

Расхождение в градусах по суставам покажет, годится ли второй способ, и заодно даст оценку шума самого эталона. Критерий годности зависит от допусков в реестре `specs/estimates.md` (E31, E32) и фиксируется после измерения.

Шаг 4. Подгонка SMPL по ключевым точкам. Нужна для эталона-меша (человекоподобный призрак). Владелец подтвердил 2026-11-09, что меш точно нужен, поэтому шаг обязательный. Для 411 последовательностей с официальными вращениями подгонка не нужна, меш можно строить сразу. Подгонка нужна для остальных 997.
- Метод: оптимизация SMPL по 3D-точкам, форма тела по танцору (30 форм), временное сглаживание, приоритет позы.
- Предел качества: у COCO нет точек позвоночника, кистей, стоп. Вращения этих частей остаются недоопределёнными, как и у официальных движений.
- Проверка: те же 411 последовательностей, сравнение подогнанных вращений с официальными.
- Требует PyTorch и библиотеку SMPL, то есть Python вне прежнего объёма импортёра. Нужно ваше разрешение по правилу про Python.

Шаг 5. Крайний вариант: заново триангулировать 3D из `keypoints2d` и камер (задача З1 в `spec/90-decisions.md`). Нужен, только если ключевых точек из `keypoints3d` не хватит по качеству.

## Что решить владельцу

- Разрешить Python для шагов 1 и 4 (разбор `keypoints3d`, подгонка SMPL). Шаг 1 внутри `tools/aist_import/`, шаг 4 за его пределами.
- Подтвердить порядок: сначала шаги 0-3, затем шаг 4. Меш на 411 имеющихся последовательностях можно начинать параллельно.
