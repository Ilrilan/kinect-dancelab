# Скоринг

> Status: draft
> Parent: [index.md](index.md)
> Источник переносимого содержимого: spec/50-scoring.md
> Происхождение: S1-S3 по словам владельца. Остальные сценарии (в том числе инварианты метрики) определены агентом по делегированию владельца 2026-11-09 («определи сам, как лучше реализовать») и требуют подтверждения.

Скоринг сравнивает движение пользователя с эталоном. Спецификация задаёт свойства метрики (инварианты), а не её значения: алгоритм остаётся свободным, пока свойства выполняются. Фикстуры для проверки свойств получаются программно из эталона, ни сенсор, ни танцы для них не нужны.

## Scenarios

S1. Цвет на скелете отражает неправильную форму движения, а не опоздание.

S2. Оценка движений может запаздывать на секунды, но выдаётся по ходу трека, не дожидаясь его окончания.

S3. По окончании трека анализ показывает, какие движения (сегменты) выполнены хуже всего и какие суставы за весь трек отклоняются систематически.

S4. Цвет не реагирует на постоянное запаздывание или спешку пользователя в пределах окна временного поиска: танцор, стабильно отстающий на фиксированное время, при верной форме остаётся без подсветки.

S5. Сравнение для цвета использует один общий временной сдвиг на всё тело, а не отдельный для каждого сустава. Сдвиг меняется плавно, ограниченной скоростью. Этот же сдвиг служит измеренной ошибкой тайминга и показывается отдельно от цвета.

S6. Интенсивность цвета непрерывно зависит от отклонения, нормированного на допустимый разброс сустава (межисполнительский разброс эталона). Порога в живой обратной связи нет, порог применяется только в итоговом отчёте.

S7. Движения в итоговом анализе оцениваются по интегралу отклонения на окне сегмента, а не по пиковому кадру, чтобы единичные сбои трекера не считались ошибками.

S8. Каждый результат объявляет покрытие: по скольким оцениваемым величинам из скольких он посчитан. Кадры с низким покрытием исключаются из анализа ошибок.

S9. Отклонение сохраняет знак: недоворот и переворот различимы в результате.

### Инварианты метрики

Проверяются на данных, синтезированных из эталона.

S10. Эталон, сравниваемый сам с собой, даёт максимальный результат и нулевое отклонение.

S11. Шум растущей амплитуды поверх эталона монотонно ухудшает результат.

S12. Сдвиг исполнения на один бит ухудшает общий результат, но оставляет его выше нуля. Постоянный сдвиг внутри окна временного поиска не меняет цвет (S4).

S13. Зеркальная перестановка левой и правой сторон ухудшает результат ниже порога на движениях, где эталон несимметричен. Проверка выполняется на сегментах с измеренной асимметрией, на симметричных движениях зеркало метрику не меняет по определению.

S14. Та же хореография на теле другого роста и пропорций даёт тот же результат в пределах допуска.

S15. Перемещение и поворот исполнителя в комнате не меняют результат формы.

S16. Уменьшение амплитуды движения (недоворот) монотонно ухудшает результат и даёт отрицательное знаковое отклонение, увеличение амплитуды даёт положительное.

S17. Исполнение с неотслеженными суставами даёт результат с объявленным сниженным покрытием, а не просто меньший результат. Состояние «стоял боком, наполовину вне кадра» отличимо от «танцевал плохо».

### Out of scope

- Сравнение результатов между треками внутри системы.
- Оценка скрутки конечностей, пальцев, кистей и стоп (вне формата позы).
