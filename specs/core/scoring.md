# Скоринг

> Status: draft
> Parent: [index.md](index.md)
> Источник переносимого содержимого: spec/50-scoring.md
> Происхождение: S1-S3 по словам владельца. Остальные сценарии (в том числе инварианты метрики) определены агентом по делегированию владельца 2026-11-09 («определи сам, как лучше реализовать») и требуют подтверждения.

Скоринг сравнивает движение пользователя с эталоном. Спецификация задаёт свойства метрики (инварианты), а не её значения: алгоритм остаётся свободным, пока свойства выполняются. Фикстуры для проверки свойств получаются программно из эталона, ни сенсор, ни танцы для них не нужны.

## Открытые вопросы

- [ ] Опора тайминга. Новичок повторяет движения за танцором на экране и по определению опаздывает на время зрительной реакции (порядка 200-300 мс по общему знанию, не замер), у выученной хореографии он упреждает по музыке. Нужно решить, что считать опорой ошибки тайминга: музыку (бит) или картинку эталона. Предложено: музыку, тогда лаг следования это честный обучающий сигнал и показатель прогресса, а не ошибка системы.
- [ ] Окно временного поиска для цвета. Окно около плюс-минус 150 мс (E20) может не покрыть лаг следования новичка, цвет начнёт показывать время вместо формы. Нужно решить: шире окно или адаптивное, подстраивающееся под текущий лаг танцора. Ширина определяется замерами на себе.
- [ ] Опережающий показ. Призрак эталона может показываться с опережением (например, на 300-500 мс), чтобы следователь успевал попадать в такт. Нужно решить, входит ли это в спек.
- [ ] Личный сдвиг синхронизации не фиксируется в профиле, пока не выяснено, как он меняется по мере обучения.

## Scenarios

S1. Цвет на скелете отражает неправильную форму движения, а не опоздание.

S2. Оценка движений может запаздывать на секунды, но выдаётся по ходу трека, не дожидаясь его окончания.

S3. По окончании трека анализ показывает, какие движения (сегменты) выполнены хуже всего и какие суставы за весь трек отклоняются систематически.

S4. Задержка системы (экспозиция и обработка сенсора, конвейер, отображение) описывается не одним числом, а оценкой с допуском: типичное значение и окно, в которое укладывается заданная доля кадров. Оценка измеряется для установки на прогретой машине. Типичное значение вычитается до любого сравнения с эталоном. Пользователь, идеально синхронный с эталоном, не получает ни подсветки, ни ошибки тайминга из-за задержки системы.

S5. Окно допуска задержки учитывается дальше по цепочке: оно расширяет окно временного поиска сдвига и входит в неопределённость измеренной ошибки тайминга. Сдвиг танцора, не превышающий окно допуска, не показывается как ошибка тайминга. Нескомпенсируемая часть (разброс, джиттер) ограничена требованием, числа в реестре оценок. Если задержка дрейфует в течение работы (нагрев, нагрузка), оценка допуска перемеряется или шире покрывает дрейф.

S6. После вычитания задержки системы цвет не реагирует на постоянное запаздывание или спешку самого танцора в пределах окна временного поиска: танцор, стабильно отстающий на фиксированное время, при верной форме остаётся без подсветки.

S7. Сравнение для цвета использует один общий временной сдвиг на всё тело, а не отдельный для каждого сустава. Сдвиг меняется плавно, ограниченной скоростью. Этот сдвиг после вычитания задержки системы является измеренной ошибкой тайминга самого танцора и показывается отдельно от цвета.

S8. Интенсивность цвета непрерывно зависит от отклонения, нормированного на допустимый разброс сустава (межисполнительский разброс эталона). Порога в живой обратной связи нет, порог применяется только в итоговом отчёте.

S9. Движения в итоговом анализе оцениваются по интегралу отклонения на окне сегмента, а не по пиковому кадру, чтобы единичные сбои трекера не считались ошибками.

S10. Каждый результат объявляет покрытие: по скольким оцениваемым величинам из скольких он посчитан. Кадры с низким покрытием исключаются из анализа ошибок.

S11. Отклонение сохраняет знак: недоворот и переворот различимы в результате.

### Инварианты метрики

Проверяются на данных, синтезированных из эталона.

S12. Эталон, сравниваемый сам с собой, даёт максимальный результат и нулевое отклонение.

S13. Шум растущей амплитуды поверх эталона монотонно ухудшает результат.

S14. Сдвиг исполнения на один бит ухудшает общий результат, но оставляет его выше нуля. Постоянный сдвиг внутри окна временного поиска не меняет цвет (S6).

S15. Зеркальная перестановка левой и правой сторон ухудшает результат ниже порога на движениях, где эталон несимметричен. Проверка выполняется на сегментах с измеренной асимметрией, на симметричных движениях зеркало метрику не меняет по определению.

S16. Та же хореография на теле другого роста и пропорций даёт тот же результат в пределах допуска.

S17. Перемещение и поворот исполнителя в комнате не меняют результат формы.

S18. Уменьшение амплитуды движения (недоворот) монотонно ухудшает результат и даёт отрицательное знаковое отклонение, увеличение амплитуды даёт положительное.

S19. Исполнение с неотслеженными суставами даёт результат с объявленным сниженным покрытием, а не просто меньший результат. Состояние «стоял боком, наполовину вне кадра» отличимо от «танцевал плохо».

### Отложено до получения сенсора

- Процедура измерения задержки системы и её допуска (S4, S5): способ внешнего эталона, прогрев, перемер при дрейфе. Решается на сенсоре, оценки в реестре E4-E9. Ограничение владельца: никаких случайных внезапных сигналов к реакции перед танцем, они напрягают нервную систему до танца. Допустимы измерение без участия пользователя, пассивное по ходу игры и спокойные предсказуемые ритмичные упражнения. Проверка задержки взмахом на случайный сигнал допускается только как отдельный режим разработки в рамках сервисной сессии, не в обычном запуске.

### Out of scope

- Сравнение результатов между треками внутри системы.
- Оценка скрутки конечностей, пальцев, кистей и стоп (вне формата позы).
