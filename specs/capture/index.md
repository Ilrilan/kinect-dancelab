# Слой захвата

> Status: draft
> Parent: [../system.md](../system.md)
> Происхождение: решение владельца 2026-11-16: сразу делать слой захвата, а не одноразовый зонд, потому что он войдёт в основное приложение. Язык C#. Остальное предложено агентом и ждёт подтверждения.

Слой захвата читает скелет с сенсора через трекер и отдаёт необработанные скелетные кадры. Первая задача: сравнить два трекера на одном Kinect v2 (родной Kinect SDK 2.0 и Nuitrack AI) по записям. Вторая: дать Player единый источник кадров (интерфейс PoseSource из CLAUDE.md), чтобы остальное приложение не зависело от трекера.

Что уже решено в системном спеке (подтверждено владельцем):

- Запись сырых данных это необработанные скелетные кадры, как их отдаёт трекер, до нормализации и конверсии (S13). Какой трекер, деталь реализации.
- Карты глубины и цвета не записываются (S13).
- Каждый кадр несёт идентификатор сенсора из сцены (S15).
- Запись сырых данных не останавливается ни при какой нагрузке (S13).

Сказанное владельцем про сравнение трекеров:

- Оба трекера на одном сенсоре одновременно запускать нереально, поэтому записи делаются отдельными прогонами на каждом драйвере.
- Простое движение повторяется 5-6 раз на каждом драйвере, затем сравнение между драйверами и дисперсия внутри драйвера.
- Язык: C# (приложение нативное для обоих SDK).

Состав:

- src/DanceLab.Capture: интерфейс PoseSource и две реализации (Kinect SDK 2.0, Nuitrack). Предложение агента.
- tools/sensor_probe/: консольная программа, запускает выбранный PoseSource и пишет файл. Предложение агента.
- Обработка записей (сравнение, дисперсия, графики): Node TS, по правилам проекта.

## Открытые вопросы

- [ ] Формат записи. Предложение: одна строка JSON на кадр (JSON Lines): время устройства и время хоста, идентификатор трекера и сенсора, список суставов с координатами в метрах и уверенностью (или признаком Inferred у Kinect SDK). Метаданные в первой строке: трекер, версия, дата, сценарий записи. Подходит ли это и для записи сессии (S13), или формат сессии определит Core отдельно, а здесь только формат замеров?
- [ ] Что именно пишем в замерах: только скелет, без глубины. Глубина порядка гигабайта в минуту, и Nuitrack не читает записи Kinect Studio. Согласны?
- [ ] Набор записей на каждый трекер. Предложение: статика лицом 10 с (E30), статика боком 45 и 90 градусов по 10 с, медленный разворот на 180 градусов за 10 с (E34), простое движение 5-6 повторов (какое именно, решаете вы), перемещение влево-вправо по зоне.
- [ ] Версия .NET. На машине .NET SDK 6.0. Microsoft.Kinect.dll из SDK 2.0 рассчитана на .NET Framework 4, поэтому слою захвата, возможно, нужна цель net48 или отдельный процесс-обёртка. Допустимо установить .NET Framework 4.8 Developer Pack или Build Tools? Решение влияет на то, останется ли весь стек на одной версии .NET (в CLAUDE.md WPF).
- [ ] C# обёртка Nuitrack: в установленном пакете её нет, она в репозитории 3DiVi/nuitrack-sdk. Допустимо подтягивать оттуда при сборке (не копировать в наш репозиторий)? Лицензия обёртки не проверена.
