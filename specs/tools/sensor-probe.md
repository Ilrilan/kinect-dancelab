# Зонд сенсора: простой ридер данных с трекеров

> Status: draft
> Parent: [../system.md](../system.md)
> Происхождение: идея и решение писать на C# принадлежат владельцу (диалог 2026-11-16). Всё остальное в этом файле предложено агентом и ждёт подтверждения.

Консольная программа на C#, которая читает данные с Kinect v2 через каждый из двух трекеров (родной Kinect SDK 2.0 и Nuitrack AI) и пишет их в файл. Нужна, чтобы по записям сравнить трекеры: шум в статике, стабильность длин костей, потери суставов, угол переворота левой и правой сторон, и повторяемость одного и того же простого движения (план владельца: 5-6 повторов на каждом драйвере, сравнить внутри драйвера и между ними).

Что именно считать зондом (одноразовая программа или консольная оболочка над будущим слоем захвата) решается в открытом вопросе о том, где живёт код.

Сказанное владельцем (дословно по смыслу):

- Делаем на C#.
- Оба трекера на одном сенсоре одновременно запускать нереально, поэтому записи делаются отдельными прогонами на каждом драйвере.
- Простое движение повторяется 5-6 раз на каждом драйвере, затем сравнение между драйверами и дисперсия внутри драйвера.

## Открытые вопросы

- [ ] Где живёт код. Предложение: зонд это не одноразовая программа, а первый кусок слоя захвата (PoseSource из CLAUDE.md, «слой захвата это одна реализация интерфейса PoseSource»). Тогда в src/DanceLab.Capture лежат две реализации (Kinect SDK 2.0 и Nuitrack), а консольная программа tools/sensor_probe/ только запускает их и пишет файл. Это дороже одноразового зонда на пару часов, но код переиспользуется в Player. Либо отдельный одноразовый зонд, а PoseSource пишем потом с нуля. Что выбираем? Рекомендую первое, так как Nuitrack и Kinect SDK придётся подключать в любом случае.
- [ ] Формат записи. Предложение: одна строка JSON на кадр (JSON Lines): время устройства и время хоста, идентификатор трекера, список суставов с координатами в метрах и уверенностью (или признаком Inferred у Kinect SDK). Метаданные в первой строке: трекер, версия, сенсор, дата, сценарий записи, число кадров. Согласуется ли с вашим представлением?
- [ ] Что именно пишем: только скелет, или ещё глубину для повторной обработки другим трекером позже? Предложение: только скелет. Глубина занимает порядка гигабайта в минуту при 30 fps, и Nuitrack не умеет читать записи Kinect Studio.
- [ ] Набор записей на каждый трекер. Предложение: статика лицом 10 с (E30), статика боком 45 и 90 градусов по 10 с, медленный разворот на 180 градусов за 10 с (E34), простое движение 5-6 повторов (какое именно движение, решаете вы), перемещение влево-вправо по зоне.
- [ ] Версия .NET. На машине .NET SDK 6.0. Microsoft.Kinect.dll из SDK 2.0 собирается под .NET Framework 4, поэтому зонд для Kinect SDK, возможно, потребует цель net48 и targeting pack. Допустимо установить Visual Studio Build Tools или пакет .NET Framework 4.8 Developer Pack для сборки?
- [ ] C# обёртка Nuitrack: в установленном пакете её нет, она в репозитории 3DiVi/nuitrack-sdk (папка с Nuitrack.NET). Допустимо подтянуть её оттуда в `tools/sensor_probe/` как внешнюю зависимость (не копировать в репозиторий, брать при сборке)?
