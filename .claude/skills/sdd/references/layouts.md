# Варианты расположения спеков

Если в инструкциях проекта не зафиксировано где живут спеки — предложи пользователю один из этих вариантов. Выбор зависит от типа проекта.

---

## A — Single-root

Все спеки в одной папке в корне репо. Подходит для небольших и средних проектов с явно выраженными доменами (бэкенды, CLI, парсеры, небольшие монолиты).

```
specs/
  system.md              ← верхний уровень: проблема, data flow
  <домен>/
    index.md             ← зачем существует домен
    <фича>.md
  changes/               ← WIP change-спеки, зеркалит структуру выше
    <домен>/
      <фича>.md
```

Когда подходит:

- Команда работает над одним продуктом целиком
- Домены логически разделены, но код живёт в одном репо без жёсткой пакетной границы
- Спеки нужны всей команде, а не только владельцам отдельных пакетов

---

## B — Co-located

Спеки живут рядом с кодом каждого пакета, как тесты. Подходит для монорепо с независимыми пакетами или микрофронтендами.

```
packages/
  <пакет>/
    specs/
      index.md           ← зачем существует пакет
      <фича>.md
      changes/           ← WIP change-спеки этого пакета
        <фича>.md
    src/
```

Когда подходит:

- Каждый пакет — самостоятельная единица со своей командой-владельцем
- Спеки пакета нужны в первую очередь тем кто работает именно с ним
- Нет значимых межпакетных фич, требующих спека «над» пакетами

---

## C — Mixed

Системные и межпакетные спеки в корне, пакетные — рядом с кодом. Подходит для крупных монорепо где есть и общая архитектура, и независимые пакеты.

```
specs/                   ← системные и межпакетные спеки
  system.md
  <кросс-доменная-фича>.md
  changes/

packages/
  <пакет>/
    specs/               ← спеки этого пакета
      index.md
      <фича>.md
      changes/
    src/
```

Когда подходит:

- Есть архитектурные решения и межпакетные фичи которым не принадлежит ни один пакет
- При этом большинство фич живут внутри конкретных пакетов
- Нужно разделить «общее для всех» и «внутреннее для пакета»

---

## Что фиксировать в AGENTS.md проекта

После выбора варианта — зафиксировать в `AGENTS.md` (или эквиваленте):

```
## Спеки

Вариант: [A / B / C / свой]
Расположение спеков: [путь или правило]
Расположение change-спеков: [путь или правило]
Домены: [список или правило определения]
```
