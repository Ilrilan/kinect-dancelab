# Делегирование сабагентам

Пользователь неоднократно терял время на сабагентах, которые уходили в бесконечную самоперепроверку. Правила ниже — вывод из этих провалов. Соблюдать всегда, без напоминания.

## 1. Делегировать точечное изучение, не писать текст

Параллелится чтение и сбор фактов. Синтез — нет.

- Хорошо делегируется: «прочитай эти файлы и выпиши API в таблицу», «проверь, есть ли такие экспорты», «найди все места вызова X».
- Плохо делегируется: «напиши раздел», «проверь раздел на противоречия», «вычитай документ». Синтез требует единого взгляда: разделы, написанные разными агентами, расходятся между собой, и ловить это потом дороже, чем написать самому.

## 2. Бриф — обязательные части

Без любой из этих частей не запускать.

1. Точные пути к файлам и каталогам. Не «найди, где лежит», а «вот путь». Разрешение путей делает оркестратор сам, одним дешёвым проходом.
2. Жёсткий бюджет: не больше N файлов и N минут. Дальше — отчёт тем, что успел.
3. Разрешённый ответ «не подтвердил». Явной строкой: «если подтверждения нет — пиши "не подтвердил" и иди дальше, это нормальный результат». Без разрешения агент считает неуверенность провалом и копает бесконечно.
4. Запрет расширять область: «не ищи другие репозитории, не ищи примеры использования вне перечисленного».
5. Последняя строка: «после отчёта остановись, дальше не ищи и не перепроверяй».
6. Формат отчёта: три короткие секции — подтверждено, неверно/неточно, пропущено. Не эссе.

## 3. Вход заморожен

Пока сабагент работает, файлы, которые он читает, не править. Иначе он перечитывает изменённый файл и начинает заново — проверено, это главный источник зависаний. Правки — после его отчёта.

## 4. Чекпойнт до первого чтения

Первым действием сабагент создаёт файл результата и пишет туда заголовок. Далее дописывает по ходу, не реже одного раза в пару шагов. При остановке должен остаться частичный результат. Если первое действие — чтение, при убийстве задачи не остаётся ничего.

## 5. Делить по артефактам, не по смыслу

Делить по непересекающимся пакетам, каталогам, наборам вопросов. Два агента на «разные разделы» одного и того же кода лезут в одни файлы и дублируют работу.

## 6. Короткие задачи

Задача на две-три минуты работает лучше одной длинной. Цепочка коротких вызовов с проверкой результата между ними — надёжнее и в сумме быстрее.

## 7. Бюджет оркестратора

Один сабагент на задачу, которую сам сделал бы за пару минут, — потеря. Перед запуском ответить себе: «я бы это сделал быстрее, чем сформулирую бриф?» Если да — делать самому.

## 8. Остановка

Сабагент не остановится сам по «достаточно». Признаки дрейфа: файл результата не растёт, агент читает то, чего не было в брифе, пишет «перечитываю, файл изменился», ищет «примеры использования». Первый признак — останавливать (TaskStop) и доводить самому по уже записанным находкам. Не ждать «пусть закончит».

## 9. Workflow

Workflow уместен для честно параллельной однотипной работы по многим единицам (сотни файлов, много репозиториев). Для двух-трёх задач чтения он лишний: оверхед больше пользы. Пользователь должен сам позвать оркестрацию словами, иначе не запускать.

## 10. Отчёт пользователю

Не описывать внутреннюю механику агентов. Сообщать: что проверено, что подтвердилось, что осталось. Отчёт сабагента пользователю не виден — пересказывать суть, а не «агент сообщил».
