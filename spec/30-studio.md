# 30. Studio — офлайновая подготовка треков

## Требование: конвейер полностью автоматический

Цель владельца — **максимальная коллекция для покрытия жанров**, а не отработать
всё самому. При сотнях связок просматривать нарезку у каждой невозможно.

Значит `датасет → готовый бандл` работает **без человека**, а редактор разметки
становится необязательным уточнением для треков, которые действительно будут
разучиваться, а не стадией процесса.

## Разделение по экосистеме, а не по приложениям

**Тонкий импортёр на Python** — только то, что требует питоновской экосистемы:

- Загрузка SMPL (модели в pickle, референсные реализации питоновские)
- Детект битов через librosa — в .NET зрелой библиотеки нет, а у датасетов
  соглашения librosa'шные (FineDance выкладывает фичи по методике AIST++)
- Преобразование SMPL → каноническая поза

Выход: нейтральный промежуточный формат (parquet + json). Запускается один раз
на трек, дальше не трогается. Порядка пары сотен строк.

**Всё остальное на C#**: нарезка на движения, редактор разметки, расчёт
коридоров допуска, сборка бандла.

Обоснование: редактор разметки — это интерфейс, то есть ровно то, где C#
дешевле; а определение канонической позы живёт там же, где его потребляет
Player.

## Нарезка на движения

Единица контента — не «трек», а сегмент. Just Dance оценивает **дискретные
движения**, и игровое ощущение создаёт обратная связь каждые полторы-две
секунды, а не один балл в конце.

Автоматический алгоритм: экстремумы скорости суставов (движение обычно
заканчивается там, где конечность останавливается) с притягиванием границ к
ближайшему биту.

### Проверка качества нарезки без человека

AIST записывает **одну и ту же хореографию разными танцорами**. Значит
автоматическая нарезка обязана давать согласованные границы у всех исполнителей
одной связки. Расхождение — сигнал, что сегментатор здесь ненадёжен.

Это даёт отсортированный список «где нарезка сомнительна» по всей библиотеке.
Просматривать руками стоит только их, и только если собираешься танцевать.

## Коридоры допуска

Считаются из **межисполнительской дисперсии**: сколько расходятся разные
танцоры на одной хореографии. Это и есть шкала, без которой метрика
бессмысленна — непонятно, 15° отклонения это ошибка или индивидуальная манера.

Ограничение данных: танцоров на жанр примерно по три, то есть на одну
хореографию порядка трёх исполнений. По трём точкам дисперсия считается с
большой ошибкой, поэтому **пулить по жанру**, а не по конкретной связке.
В брейкинге разброс принципиально больше, чем в джазе, так что единый набор
порогов на все жанры неверен.

## Диагностика импорта

Проецировать **эталонный** скелет в кадр видео по известным параметрам камеры.
Если motion и видео разъехались по времени или взят не тот ракурс, наложение
покажет это мгновенно. В двух панелях рядом такое легко не заметить.

Это инструмент сборки, не фича плеера.

## Чего в Studio нет

Проекции **своего** скелета на видео танцора. У видео нет глубины, значит
правильный порядок перекрытия не построить — скелет будет рисоваться поверх
конечностей, которые в реальности перед ним. Плюс пришлось бы поставить своё
тело туда, где стоял танцор, выбросив собственное положение.
