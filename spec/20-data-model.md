# 20. Модель данных: четыре яруса

Классификация по **двум осям** — воспроизводимость и изменяемость. Их смешение
было ошибкой первой итерации.

| Ярус | Воспроизводим | Изменяем | Где живёт |
|---|---|---|---|
| Бандл трека | да (из датасета) | нет | файлы |
| Запись сессии | **нет** | нет | файлы, источник истины |
| Профиль | **нет** | **да** | файлы, append-only |
| Производный кеш | да | да | файлы, выбрасываемый |
| Агрегаты | да (из записей) | да | SQLite, выбрасываемый |

## Бандл трека

Общий, неизменяемый, **независимый от тела**.

```
manifest.json      id, название, источник и атрибуция, BPM, длительность,
                   версия формата, версия скрипта извлечения,
                   ссылки на локальные аудио и видеофайлы (не сами файлы)
reference.parquet  эталон: вращения по кадрам (не позиции!)
angles.parquet     производные эталонные углы
beats.json         битовая сетка
moves.json         границы сегментов, веса сложности
tolerances.json    коридоры допуска по суставам
cameras.json       параметры камер по ракурсам (AIST++)
```

**Хранить вращения, а не позиции.** Тогда подстановка формы тела — одна
операция, и один бандл работает для любого профиля.

Версия формата и версия скрипта извлечения обязательны: определение канонической
позы будет меняться, и без версии старые треки начнут молча ехать.

## Запись сессии

**Неизменяемая, только дописываемая. Это и есть прогресс пользователя.**

Один файл на сессию: канонические позы по кадрам, таймштампы, ведомый сдвиг
тайминга, отклонения по суставам. Порядка килобайт в секунду, трёхминутный
трек ≈ 1 МБ.

Запись штампует **версии всего, что её породило**: формат позы, допуски, кривая
отображения, версия трекера, **версия профиля**. Без этого «улучшение» на
графике прогресса будет неотличимо от подкрученного параметра.

Глубина не пишется — реплей рисует скелеты.

## Профиль

Единственное, что **изменяемо и незаменимо одновременно** — самая опасная
категория, при том что самая маленькая.

Поэтому **append-only**: не перезаписывать `profile.json`, а писать
`profile/<дата>.json`, текущим считается последний. Даёт историю калибровок,
защищает от неудачной записи и позволяет записи сессии сослаться на версию.

Содержит: коэффициенты формы тела (SMPL betas), длины сегментов из калибровки,
настроенные параметры отображения.

Калибровка тела измеряется **один раз** и заморожена. Перемеряется только
осознанно.

## Производный кеш

На пару трек × профиль: подставленная форма тела и **переприземлённая**
траектория корня (после подстановки формы стопы перестают совпадать с полом,
нужна подгонка высоты корня и масштабирование перемещения по отношению длин ног).

Регенерируемый и выбрасываемый. Смена версии не требует миграции — просто
инвалидирует кеш.

> Правило: всё, что зависит от профиля, идёт в кеш, а не в бандл.

## Агрегаты

SQLite. По сессии и суставу: медиана отклонения **со знаком**, p90, покрытие,
дата, трек, версии. Десятки тысяч строк за годы — ничтожно.

База **выбрасываемая**: повредилась — удалил и перестроил из записей сессий.

Требования переносимости (на случай переезда на Postgres):

- Настоящие типы, а не динамическая типизация SQLite
- Идентификатор сессии — UUID, сгенерированный локально; никакого `AUTOINCREMENT`
- Время — явный UTC в ISO-8601
- Без SQLite-специфичного SQL (`INSERT OR REPLACE`, `strftime`)
- Отклонения — double
- **Никаких абсолютных путей**: всё относительно корня данных
- WAL включён

## Сохранность

- Записи сессий уезжают **по событию**, не по расписанию: дотанцевал — ушло.
  Локальный спул незагруженных на случай недоступности хранилища.
- **Ничто в тракте «дотанцевал — записалось» не ходит по сети.**
- GFS-ретенция на кластере. Прореживание не ради места (объёмы ничтожны), а
  ради окна на обнаружение незамеченной порчи.
- Шифрованный архив наружу, записанный однажды, а не синхронизируемая папка:
  синхронизация честно разносит и удаление, и порчу.
- Воспроизводимое (бандлы, датасеты) наружу не выносить.
- Проверка восстановления раз в полгода.
