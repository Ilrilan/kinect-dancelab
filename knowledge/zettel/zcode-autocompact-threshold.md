Механизм (расследовано по бандлу zcode.cjs, клиент 3.17.2.9661, 2026-11-21):

- Автокомпакт включён по умолчанию, решение принимает функция: порог =
  эффективное контекстное окно выбранной модели − буфер 13 000 токенов.
- Окно приходит из свойств модели при её выборе (ModelSelected), дефолт
  200 000, если модель не декларирует.
- Пользовательской настройки порога нет: ~/.zcode/cli/config.json (ключей
  нет), Settings UI (пункта нет), local_setting в базе клиента (пусто),
  провайдерские конфиги (только доступ к API). Плагины не помогают: их API
  (скиллы, команды, хуки 7 событий, MCP, агенты) до внутреннего порога не
  дотягиваются.

Запрос фичи отправлен 2026-11-21 через официальную форму фидбека ZCode
(zhipu-ai.feishu.cn, «ZCode User Feedback!»): вынести порог автокомпакта в
конфиг и Settings, например `autoCompact.thresholdTokens` / `bufferTokens` /
`thresholdPercent`, с переопределением на модель и клампингом к реальному
окну. Пример из запроса: `{"autoCompact":{"enabled":true,"thresholdTokens":500000}}`.
В форме проставлена NPS-оценка 10 от имени владельца (агент сообщил владельцу
отдельно). Поле контакта оставлено пустым.

**How to apply:** после обновления клиента проверять Settings и changelog на
появление настройки автокомпакта; при появлении настроить порог 500к и
перевести заметку в «решено». До тех пор компакт остаётся автоматическим на
пороге окна модели, потерю контекста компенсирует дисциплина чекпойнтов
([[general-working-rules]]).
