## Темп и чекпойнты

- Не более 5 минут работы без фиксации в файл: результат этапа сразу в статус, журнал или память.
- Рабочая итерация 20-40 минут, затем: журнал, память, сброс контекста.
- STATUS/HANDOFF актуальны всегда: сессии рвутся, обновлять после каждого шага. Закрыл задачу → коммит сразу.
- Работать открыто: план «сейчас/дальше» до команд, статус текстом, не исчезать в bash.
- При словах «сброшу контекст»: выдать готовый промт восстановления сессии.

## Границы инициативы

- Вопросы закрывает владелец. Перед записью «закрыто» тест: появилось правило, которое можно вписать в документ? Нет → вопрос открыт, даже если владелец писал по теме.
- Правка формулировки, исправление описания, указание на ошибку ≠ ответ на вопрос. В статус пишется дословная цитата ответа, не слово «закрыт».
- Уточнение по тексту = дополнение к одобренному, не замена. Замена блока согласуется: перечислить, что уйдёт, и спросить. Файлы проекта не трогать до подтверждения по каждому пункту.
- Не ресёрчить лишнего: готовый паттерн в контексте применяется сразу; сначала README пакета, потом grep по .d.ts.
- perf-анализ: только планирование, фиксы по явному запросу.
- Ревью жёсткое состязательное, без приглаживания. Integrity: красная линия, защитные дисклеймеры и нейрослоп убираются.

## Делегирование

- Сабагенты только через скилл subagent-delegation: точные пути в брифе, бюджет, замороженный вход, чекпойнт до первого чтения. «Не подтвердил» = не подтверждено. Дрейф агента → остановить и делать самому.
- Полный обход документов при обновлении скиллов: спавнить агента на весь корпус, не выборочно.

## Стиль текстов

Относится к любым текстам, которые агент пишет для владельца и от его имени: спеки, документация, коммиты, отчёты, ответы в чате, заявки, PDR, вики, деки (уточнено владельцем 2026-11-09: не только рабочие тексты).

- Без жирного. Заголовки секций: plain text с точкой («Роль.»).
- Без длинных тире. Там где тире играло роль запятой: «:», «.», «,» или переписать предложение.
- Пустая строка перед каждым списком и таблицей, включая вложенные под-списки: иначе Confluence схлопывает в одну строку.
- Стрелки (→) только как техническая нотация (938k→42k, статусы Jira). Причинность в прозе: «так как», «потому что», «следовательно».
- Короткие предложения, одна мысль на предложение. Абзац с тремя и более однородными элементами → вложенные списки.
- Русский. Профессиональные термины, имена, код не переводить: XaaS, semver, CI, OKR, KR, RFC, TL;DR, hands-on, span. Разговорный англ-жаргон с русским эквивалентом заменить русским.
- Устная реплика ≠ текст деливерабла: смысл переносить, формулировку переписывать в докладный регистр. Дословно только по явной диктовке.
- Подлежащее живое: «я», «мы», «команда», не «масштабирование» и «делегирование».
- Запрещённые обороты: леверидж, people-сигналы/people-радар, by construction, outcome-gated, toil, мета-скобки «(ключевой аргумент)», «Связующая нить:», «X не Y» защитные дисклеймеры, блоки «Честно:».
- PDR/Минто: один статус на головном уровне, корень не симптомы, термины ролей, читатель укладывается в 20 минут.

## Верификация и скрипты

- Каждое нетривиальное изменение с тестом. Полный прогон после правок: типы + тесты + линт + prettier, все четыре.
- Скрипты, пробы, разбор логов: только Node TS через ts-node/tsx. Python и sh-логика не используются. Исключение (уточнено владельцем 2026-11-09): необходимый минимум на Python там, где используются чужие готовые внешние инструменты. В DanceLab это весь импортёр `tools/aist_import/` целиком, включая SMPL→канон и подгонку SMPL по ключевым точкам (разрешено 2026-11-09: «Если понадобится питон здесь делай на питоне»): «нет смысла вводить ещё одну архитектурную границу». Всё остальное, что агент пишет с нуля, только Node TS. Python где-либо ещё только при объективной и сильной причине и только после обсуждения и разрешения владельца; молча не добавлять.
- Не дублировать механизмы: модифицировать существующий стор, транспорт, атом; параллельный не создавать.
- SDD: код только после подтверждения контракта; статусы draft/scenarios/realisation/done; Tasks-секции при переходе в `done` удаляются, история в git (уточнено владельцем 2026-11-09: прежнее правило «не удалять» было для чата без git); docs = статичный снимок.
